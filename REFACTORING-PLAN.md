## P1. Убрать подтверждённую лишнюю работу

### B1. Сократить число запросов метаданных архива Board

`Store._paths()` на каждом опросе проверяет все архивные папки и выбирает 50 новейших по `mtime` файла `state.json`. Начать с переиспользования метаданных от `os.scandir` и одной проверки `lstat` на архивный файл, сохраняя отказ от перехода по символическим ссылкам. Замерить результат до решения, нужен ли индекс. Запись в существующий `state.json` может обновить его `mtime` без изменения `mtime` каталога задачи и корня архива. Обновление должно оставаться видимым для опроса.

Готово, когда p95 холостого `Store.poll()` на 5 000 архивных записях укладывается в предварительную цель 70 мс, а следующий опрос по-прежнему учитывает добавление, удаление, перенос задачи в архив и изменение `state.json`. Сохраняются порядок и лимит выдачи, прямой доступ к старым архивным задачам и поведение при нечитаемых файлах. [Источник](board/server/src/teamster_board/store.py#L386) · [Проверки](board/server/tests/test_store.py#L100)

Реализовано через `os.scandir()` и один `lstat()` на каждый `state.json` при отборе. В парном замере с `476af8e` p95 снизился с 3,57 до 3,11 мс при пустом архиве, с 32,23 до 15,48 мс при 1 000 записях и с 144,54 до 58,71 мс при 5 000 записях. При 5 000 записях p50 снизился со 124,51 до 53,36 мс, а число вызовов Python `os.stat` и `os.lstat` за опрос — с 30 806 до 5 606.

В замере было по 100 завершённых задач вне архива, без PID и журнала. Каждый `Store` получил один прогрев и 35 холостых опросов на той же фикстуре. Порядок вызовов двух версий менялся между замерами. Снимки, детали и события совпали при добавлении записи, изменении `mtime` существующего файла, повреждении и удалении состояния, переносе задачи в архив и наличии символических ссылок. ### W1. Читать новые данные rollout по мере поступления

При каждом изменении размера rollout монитор перечитывает суффикс с начала текущего запуска. Завершение отдельно читает настройки модели, лимиты и токены. В первом PR изменить путь периодического чтения. Позиция внутри запуска должна учитывать только обработанные данные, сохранять неполный хвост и давать корректный результат после усечения или замены файла. Сведение финальных проходов рассматривать отдельно после профиля. Для 30 пакетов по 500 строк на обычном дописывании целиться в однократную обработку каждой полной строки при опросе. В отдельном прогоне с длинным префиксом возобновлённой сессии проверить, что он обходится по прежним правилам.

Проверить порядок учёта недельных лимитов по обе стороны сброса, новые и запоздавшие сэмплы, токены, последний результат, отмену, ротацию и завершение на границе бюджета. Сравнивать решения монитора и финальный итог с базой, включая сценарий с частично записанной строкой. [Опрос](src/teamster/turn_monitor.py#L334) · [Парсер](src/teamster/threads.py#L193) · [Недельный бюджет](tests/rotation_weekly_budgets.py#L424) · [Телеметрия](tests/rotation_telemetry.py#L1118)

Монитор продвигает позицию только после полной строки и переоценивает последний валидный лимит при добавлении событий другого типа. При обнаруженном усечении или замене файла он возвращается к байтовой границе текущего `exec`. Эту же границу использует финальный расчёт настроек и токенов. Добавить вердикты, переиспользованные slug, старые строки и запрос одного slug. Если профиль подтверждает дорогой поиск задачи для каждого вердикта, ограничить поиск кандидатами из группы `(repo, slug)` в памяти одного запроса. ### F1. Сократить критический путь первого открытия карты

Инициализировать сцену с текстурами галактики. Загрузку кораблей, планет и станций привязать к первому входу в систему или к фоновой загрузке после первого кадра. На холодном открытии измерить сетевые байты и запросы до первого интерактивного кадра, затем отдельно измерить первый вход в систему. Цель — вывести ресурсы режима системы из ожидания первого кадра и получить измеримый выигрыш p95 при том же сетевом профиле. При выборе момента фоновой загрузки проверить, что задержка перехода в систему остаётся приемлемой, а текстуры повторно используются при навигации. Пройти ошибки загрузки, повторное открытие и восстановление WebGL. [Загрузка сцены](board/web/src/map/scene/index.ts#L29) · [Загрузка текстур](board/web/src/map/scene/kit.ts#L24)

Галактика загружает `nebula` и `sun`. При первом выборе системы загружаются общие текстуры кораблей, станций и планет, затем создаются слои с последними данными выбранного репозитория. При долгой загрузке перелёт ждёт под затемнением, а HTML-метки появляются по завершении отрисовки. В режиме reduced motion карта ждёт текстуры без перелёта. Ошибка обязательной текстуры открывает резервный экран с повтором. [Общие текстуры](board/web/src/map/scene/kit.ts#L29) · [Слои системы](board/web/src/map/scene/index.ts#L109)

## Порядок PR и критерии завершения

- P0 открывает три независимых направления. Первый PR сервера — B1, worker — W1, интерфейса — F1 после браузерного замера. W2 может идти независимо от W1. На одном рабочем контуре сначала сравнить эффект оптимизации, затем делать структурный перенос того же кода.
- R1 можно выполнить отдельно от B1 и F1. R2 предшествует R3, B1 предшествует R4. Для PR сохраняющего поведение выполнить `/usr/bin/python3 -I tests/compare_rotation_assertions.py --base origin/main` и перечислить каждое расхождение в PR. Для изменения диспетчеризации дополнительно сравнить help через `tests/compare_cli_help.py --base origin/main`. [Правила репозитория](AGENTS.md)
- Worker остаётся на Python 3.9+ и стандартной библиотеке, Board остаётся отдельным приложением. Сохранить CLI, относительные пути, текущий и legacy data home, старые `state.json` и журналы, совместимость установленного CLI и контракт Board v1. Соблюдать существующие правила модулей. Изменение схемы состояния оформлять отдельно с `STATE_FIELDS` по правилам выпуска. [Правила модулей](src/teamster/__init__.py) · [Контракт Board](board/CONTRACT.md)
- Запускать целевые тесты worker через `python3 -I tests/test_rotation.py <селекторы>`. Полный набор запускать не больше двух раз за задачу, без замера его времени и без `CODEX_TEST_JOBS=1`. Для Board server использовать `uv run --project board/server pytest board/server/tests -q`, для web — `npm --prefix board/web run build` и `npm --prefix board/web test -- --run`. Для новых граничных случаев дополнять существующий тест. Проверки используют временные homes и фейки, реальные `codex`, `claude` и `security` запрещены правилами репозитория. [Worker CI](.github/workflows/test.yml) · [Board server CI](.github/workflows/board-server.yml) · [Board web CI](.github/workflows/board-web.yml)
- Для цикла задач результат считается сохранённым, если совпадают результаты работы и проверок, переходы при остановке и восстановлении, журнал и число внешних действий. Изменения моделей или правил ревью требуют отдельной оценки по `report`. Для сопоставимых задач сравнить время, токены, доли `done` и `accepted`, число замечаний P1/P2 и повторных ходов. [Качество и стоимость](src/teamster/docs/telemetry.md#compare-executors-and-reviewers)
- Этап завершён, когда для каждой задачи P1 есть сравнение до/после и результаты проверок, для каждой задачи P2 есть отдельный проверяемый diff, а кандидаты P3 либо оправданы замером, либо отложены с указанием метрики и результата. Версии в рабочих PR не менять.
